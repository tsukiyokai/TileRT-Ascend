# Two-rank layer-chain graph contract

The frozen v1 harness passed the a3-194 physical dies6/7 graph gate: M1/2/12/32 × eight changing inputs per rank, eight official captures, 64 explicit replays, 7,232 raw-byte comparisons and 256 actual HCCL2 ordered-sum checks. All 904 capture-before/after boundaries remained unchanged until explicit replay; replay made no Python calls. The communication window retained the same stream and lifetime across widths. The [independent device summary](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/vendor-hook-tp-graph-wide-v1-a3-194/summary.json) records both rank reports and frozen identities. This is a numerical graph gate with BF16 HCCL2 as the oracle; it does not measure the project's FP32 reduction path.

The preceding actual Torch 2.12 CPU gate passed 21 eager contracts, eight graph contracts, five DSO loads, 835 overlay hashes and 7,953 runtime hashes without mapping or initializing an NPU. The [frozen harness and CPU report](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/vendor-hook-tp-graph-harness-v1/README.md) identify the sources and image.

The candidate captures two frozen TP-layer launches, the persistent top-k copy between layers6/7, and preallocated immediate output/residual consumers through the official `ACLGraphWrapper`. The oracle remains eager: the original input norm and accepted attention/FFN parents, with an actual two-rank HCCL SUM at both reduction sites. It retains 113 raw boundaries per rank and the rank-distinct partial/identical reduced-output gates. The two shards retain TP16 local geometry; this does not validate a TP16 model or full-rank collective.

An unentered real `torch.npu.graph(UpdatableGraph())` owns the default capture stream before SHMEM initialization and window allocation. Both the manager and graph are retained. The actual runnable and every replay must use that exact stream. All parent tensors, communication buffers, static metadata, capture outputs and C ABI packets are allocated before capture. The window survives all widths and replays without host epoch resets.

Capture must enter the runnable once, retain the official graph object and all output pointers, and leave every poisoned observation/cache byte unchanged until the first explicit replay. Each replay changes input values, actual lengths, independent page plans and cache contents in the existing owners. One rank is delayed in alternating rounds. The runnable counter and official capture counter must remain unchanged during replay. A width's graph is reset before its owners can be released; all graphs are gone before the window is collectively freed.

CPU tests verify frozen parent extraction, the two HCCL seams, stream and owner rejection, close ordering, and the actual Torch212 nonmember group path. Device capture and numerical results require a separate runner report.
