# Four-credit down consumer

This child starts from frozen down-overlap build-v2, library `1d4220181c3a0235109d663aa348c4b435d9e5f91bdb8e82e0201e82c8214822`. Its ancestor is the uninstrumented composed `3673c2a7` implementation. The only scheduling change is AIV consumption of four ready tiles as one contiguous 512-column span per worker. Matmul calls, publication, producer credit limits, tail drain, numerical helpers, scratch, host validators and all phase barriers remain unchanged. The independent namespace is `tilert_ffn_down_batch`, C ABI `ffn_down_batch_launch`.

The down result has one M tile and 24 increasing N256 tiles per expert. The installed CANN N loop advances its inner index from zero; both supported M/N loop orders reduce to the same N sequence when M has one tile. `GetTensorC(c,0,false)` writes the current tile using original row stride 6144. Its following PIPE_FIX ready publication orders the output copy before either AIV consumes that credit. Four ready waits therefore cover a complete 1024-column span. AIV0 reads its first 512 columns and AIV1 its second 512, retaining the same compact high/low planes and original-slot stores.

Each consumer completes its 512-column stores before returning four free credits on PIPE_MTE3. Mode2 requires both workers' credits before an AIC wait completes. The producer can publish the first four tiles without a returned credit; it may compute the fifth tile into L0C while waiting, but cannot publish that result until credit is available. Thus the batch cannot deadlock on a window of four. A window of three would stop with three published tiles and both consumers waiting for a fourth; a CPU state-space test retains this counterexample. All 24 tiles divide into six batches, so a batch never crosses an expert. Zero-count experts produce no credits. The original continuous sequence and final drain consume every ready/free count before the unchanged barrier 4 and the next replay.

The child adds no GM or UB storage; peak resident UB remains 112352 bytes. It reduces helper invocations from 48 to 12 per route, and activation-scale copies from 48E to 12E for E active experts. For M12/E65, that changes 3120 to 780 copies. The composed ancestor uses 192 for this fixture. Effective INT32 input and BF16 output bytes remain unchanged, as does expert-local ownership; these remaining costs can still outweigh overlap. Build-v2's roughly 100 us regression is not evidence that this child recovers that time.

Seven CPU contracts check actual frozen-source scope, all supported row/group address partitions, both compact planes, mode2 two-consumer interleavings, missing tail drain, batch/window deadlock and expert-boundary conservation. Compilation verifies the same installed SDK hashes and host tiling guard. Device acceptance must retain all 30 boundaries against both the separate native chain and the official numerical chain. Performance requires a same-address full-FFN comparison against the composed ancestor, with both owner arenas, changing-route gates and at least 30 independent event samples per arm.

The CANN 9.2 build `c83c9cb66f9109b810023d95794a4907734e73f66b9526ffd0c3b5987e63d984` passed the M12/24-group single-die gate: eight candidate and sixteen reference changing-input graph replays produced 480 exact raw-byte comparisons across all 30 boundaries. Both the separate native chain and official numerical chain matched. The [device summary](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/ffn-down-batch212-m12-v1-a3-194/summary.json) records report `d9a14746141e617658f7fbfebe42f4b416066b968edeaa73c477014a11227fe2`. This covers the rank-local FFN at that geometry; TP and model latency are outside the gate.

The [matched-address timing](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/ffn-down-batch-timing-v1-a3-194/summary.json) rejects this child. At M12/24 groups, E65, 16 banks and 16 calls per graph, its two owner arenas measured candidate/base medians of 296.410/234.015 us and 297.731/238.865 us. Paired median savings were −62.431 us and −58.885 us; all 60 pairs were slower. The 19,200 raw-byte boundary checks and 360 event-tail checks passed. Each arm had 30 independent event samples, with 30 graph replays per sample. These are complete rank-local FFN measurements against `3673c2a7`, excluding TP. Four-tile batching reduces the extra store work but does not establish a useful overlap schedule; this microtile family is not selected.
