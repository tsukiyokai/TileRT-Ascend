# Two-rank layer-chain contract

The eager device gate passed on a3-194 physical dies6/7: M1/2/12/32 × eight changing inputs produced 7,232 exact raw-byte boundary checks and 256 actual HCCL2 ordered-sum checks. All 16 processes exited normally; only ranks0/1 initialized NPUs. Both ranks retained distinct projection/expert partials, equal replicated inputs and reduced outputs, and the same communication window across widths. The [independent device summary](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/vendor-hook-tp-chain-wide-v2-a3-194/summary.json) records library C2 and fixture v2 identities. This result covers eager execution; graph replay and timing have separate gates.

The first gate compares the frozen TP-layer entry with separate local parents and real two-rank HCCL SUM calls at both reduction sites. It uses two controlled TP16-shaped shards: four local attention heads, 128 local expert intermediate channels, and unchanged layer6/full-indexer and layer7/shared-indexer selection. It does not claim TP16 model equivalence.

For each rank and each layer, the oracle computes `(u, rho) = input_norm(x, residual)`, attention partial `a = attention(u)`, `A = HCCL2_SUM(a)`, `(b, eta) = FFN(A, rho)`, and `B = HCCL2_SUM(b)`. The next layer receives `(B, eta)`. The retained residual is not added to `B`. Norm, router, compressed QKV and indexer parameters are replicated; projection and expert matrices differ between ranks. Partial attention and FFN hashes must differ across ranks, while both reduced tensors and retained residuals must agree.

The oracle preserves the accepted local fixture's 109 boundaries and adds four reduction results across layers6/7, yielding 113 comparisons per rank and input. Each HCCL result is also checked against the actual two captured BF16 partials summed in rank order in FP32 and rounded once to BF16. This checks the installed two-rank arithmetic, including zero signs, without extrapolating its order to TP16.

The eager gate uses one declared serialized stream per device. Both ranks initialize a fresh MTE-only SHMEM world, collectively allocate the same capacity-32 window, and preserve its epoch through both layers and every changing-input case. A layer advances the epoch twice; two layers advance it four times. Neither cache reset nor output poisoning may touch the communication window. Its size is 1,573,184 bytes per rank; four independent `[M,6144]` BF16 reduction outputs across two layers require another `8*M*6144` bytes. Every parent host validator runs before the C ABI.

The later official graph gate needs a separate stream contract. The installed TorchNPU 2.12 `graph` constructor creates or returns its class-level `default_capture_stream`; capture starts only in `__enter__`. Construct and retain an unentered graph manager first, allocate the SHMEM window on its `capture_stream`, and require the real runnable's stream to match it. The official wrapper omits a stream argument and therefore selects this same default. No SHMEM allocation occurs inside capture. The [pinned source evidence](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/layer-tp-chain-protocol-v1/sources.json) records the exact image and hashes.

Before releasing a window, stop submission, synchronize both devices, destroy every graph, and rendezvous all participating ranks. Free windows in collective allocation order, then finalize SHMEM. The real 16-rank Gloo groups establish constructor geometry; only ranks0/1 initialize NPUs, each keeps its original singleton MC2 metadata group, and a separate HCCL world of size two supplies the oracle reductions. Fourteen CPU participants must remain uninitialized on NPU.
