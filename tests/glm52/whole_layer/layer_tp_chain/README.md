# One-launch layer with TP reductions

This experimental entry composes input AddRMSNorm/A8, indexed or shared-indexer attention, attention-output AllReduce, complete NZ FFN and FFN-output AllReduce in one mixed AIC/AIV launch. It uses the frozen local-chain source from `609c973e`, the static-GU FFN parent and SHMEM communication phases with 24 core groups.

The current serial FP32 reduction differs from the installed deterministic HCCL tree in a [three-rank device diagnostic](../communication.md). At M1 and M12, BF16 partials `[1, 2^-25, -1]` yield zero in the native reducer and `2^-25` through the original FP32 HCCL arithmetic. All 36 eager/graph cases reproduce the respective serial and tree oracles; runtime logs confirm `AllReduceMeshAivFor91093Executor`, FP32 SUM and deterministic execution. The two-rank results below remain valid. Matching the selected HCCL order is required before this entry can replace the original multi-rank reduction.

The [two-rank eager comparison](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/vendor-hook-tp-chain-wide-v2-a3-194/summary.json) passes M1/2/12/32 with eight changing inputs per width. Across two consecutive indexed/shared-indexer layers, 7,232 intermediate byte checks and 256 real HCCL SUM comparisons pass. Rank-local projection and expert weights differ; reduced outputs and retained residuals match across ranks. The capacity-32 window remains live across all widths and inputs without host epoch resets. Two A3 dies execute; fourteen CPU peers supply only TP16 constructor geometry.

The [official ACLGraphWrapper comparison](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/vendor-hook-tp-graph-wide-v1-a3-194/summary.json) passes the same four widths and changing inputs. Across both ranks, eight captures and 64 explicit replays pass 7,232 intermediate byte checks and 256 HCCL comparisons. All 904 observed boundaries remain unchanged during capture, and no Python runnable executes during replay. The window retains the actual capture stream through every width, then closes after graph destruction and the rank rendezvous.

The [M12/24 paired measurement](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/vendor-hook-tp-timing-m12-v1-a3-194/summary.json) compares C2 against same-address native norm, attention, FFN and FP32 HCCL2 reductions, including both BF16/FP32 conversions. Two retained compute arenas give control/candidate p50 values of 1148.304/1125.374 and 1153.384/1130.584 µs per two-layer pair. Paired savings are 23.049 and 23.264 µs; all 60 pairs favor C2. Each graph contains 16 repeated pairs, each event 30 replays, and the per-arm statistic takes the larger of the two rank intervals. The separate one-pair series saves 32.449/31.283 µs with 59/60 wins. All 23,492 production, literal-conversion and post-event byte checks pass, together with 1,808 unchanged capture boundaries. This measures combined launch fusion and SHMEM/HCCL choice on two controlled shards with one repeated weight bank per arena. The [fixture contract](../vendor_hook_tp_timing/README.md) records owners, idempotence and event boundaries.

The [CANN build](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/layer-tp-chain-build-v1/summary.json) compiles both entries and links without undefined symbols. Torch212 loads library `c2b72e46` with no mapped NPU; eight M/rank geometry contracts pass. The host ABI also co-loads with the local parent and rejects ten invalid or uninitialized calls without initializing the NPU.

Each reduction accumulates BF16 rank partials in ascending rank order in FP32, then rounds once to BF16. The eager and original graph gates check the installed BF16 HCCL2 result against both actual partials with this arithmetic. The engine's [`_tp_reduce`](../../../../tilert/models/glm_5_2_ascend/cann_model.py) converts BF16 inputs to FP32 before its collective and converts the result back to BF16. The paired measurement includes that arithmetic and DMA path with preallocated FP32 control buffers; literal conversion remains an external numerical check. Its measured environment is `HCCL_OP_EXPANSION_MODE=AIV`, `HCCL_DETERMINISTIC=true`, with no `HCCL_ALGO` override. TP16 still requires comparison at its actual rank count; these two-rank measurements do not establish model TPOT. The reported `graph_tasks=0` is the length of `UpdatableGraph.tasks`, not a device launch count.

Attention publishes its output and resets the pipe before the first reduction. A phase barrier follows that reduction before FFN consumes its result. FFN receives another publication barrier before its in-kernel consumer; the second reduction itself joins all participating cores. Communication buffers use 20 KiB of the reset AIV arena. The argument record contains 1,648 bytes.

The host API retains the local-layer records and two separate BF16 reduction outputs. Initialize one SHMEM context per rank, then allocate the same window capacities in the same order on every rank before capture. A window belongs to its creation device and submitted stream. Consecutive layers and graph replays on that serialized stream can reuse it. Destroy every graph and synchronize every participating rank before closing windows; finalize SHMEM after all windows are closed.

`prepare.py LOCAL_BUILD NEW_OUTPUT` verifies the local library and frozen sources and copies the communication implementation. `build.py` verifies the recorded SHMEM revision, headers and libraries, compiles with CANN 9.2, and loads the resulting C ABI under Torch212 with no mapped NPU. The build does not initialize SHMEM or execute a device kernel. Parent operators remain responsible for validating tensor shapes, storage formats, tilings and cache metadata before local-record preparation.
