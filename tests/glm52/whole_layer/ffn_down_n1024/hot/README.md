# Hot-expert Down M-tail gate

This gate compares the frozen N1024 FFN with the original DecoderLayer norm and MLP at M=17 and M=32. The original gate and router retain their shared FP32 correction-bias allocation; the first eight entries become +4 and all others -4. Since sigmoid scores lie in [0,1], the selected set must be experts 0..7. Selection order and probabilities still come from the original router.

Every changing-input replay requires all tokens to select the eight experts exactly once. It compares native IDs and FP32 probabilities with the observed original values, then independently derives and checks all 256 counts and all 264 active-table words, including unused zeros. Thus each active expert has c=M: M=17 exercises a two-row second M32 tile, and M=32 exercises two full tiles. Both 16 and 24 block groups are supported.

The original eleven output checks, four same-graph immediate consumers, and complete 200-byte Down-tiling checks remain. Route probabilities and floating outputs are poisoned with NaN; counts start at zero and the active table starts at one with E=0. The observer returns the original router objects unchanged and clones its values on the producer stream. Original norm, gate, routing, GMM and shared-expert arithmetic is unchanged. This is a numerical coverage gate, not a timing workload.

The staged library is the same frozen N1024 DSO as the random-routing gate. Six CPU contracts passed on x86 and on the actual ARM Torch2.12 runtime; the DSO loaded with NPU initialization false. All 793 staged file identities were verified on a3-194. [Frozen source, CPU results and launch arguments](../../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/ffn-down-n1024-hot-build-v1/summary.json) record the scope.

The [24-group run](../../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/ffn-down-n1024-hot-b24-v1-a3-194/summary.json) and [16-group run](../../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/ffn-down-n1024-hot-b16-v1-a3-194/summary.json) both pass on one idle A3 die. Each covers 32 cases: two layer weight sets, M17/32 and eight changing inputs. All 480 raw-byte checks, including 128 immediate-consumer and 128 routing-metadata checks, and 36 complete tiling checks pass per run. All sixteen Gloo processes complete; only rank0 initializes the NPU. These runs preserve the original bias owner and verify that every selected expert receives all M tokens.
