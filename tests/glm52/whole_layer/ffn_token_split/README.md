# Token-owned MSD input split

This isolated candidate starts from the validated complete FFN library `8430ef17d068ce5a1cdbe4915ba189ca38c666322d8726a42091f8acb3b36f84`. It changes only the phase-one input split: one AIV owns each `(token, 2048-column tile)`, converts its A8 values into the existing signed INT4 high/low representation once, and scatters those same packed bytes to all eight expert-major routes. The namespace is `tilert_ffn_token_split`; the C entry is `ffn_token_split_launch`.

For original slot `o = token * 8 + slot`, the existing source/slot permutation gives sorted route `r = inverse[o]`. With that slot's expert prefix `b` and count `c`, the high row is `2*b + (r-b)` and the low row is `2*b + c + (r-b)`. Both have stride 6144 INT4 elements. Each expert occupies exactly `[2*b, 2*(b+c))`; all expert segments partition the unchanged `2*R` rows. The input contract requires eight distinct valid experts per token and a complete source/slot permutation, giving `c <= M <= 32`. Order within an expert may be arbitrary. No host reads or new device validation are introduced.

The scalar inverse and original expert IDs reuse the first 2048 bytes of the existing 8448-byte INT32 staging buffer. `MTE2_S` precedes metadata reads; a UB data barrier completes inverse scalar writes before scalar consumption. The original INT8-to-FP16-to-FP32 conversion and `SplitHalves` operations remain unchanged. High bytes use the existing packed buffer. Low bytes use the input buffer only after vector conversion has consumed all A8 values. A vector-to-MTE3 fence publishes both packed buffers, and MTE3-to-vector plus MTE3-to-MTE2 fences protect their reuse after all sixteen stores. Every route is written, including zero-probability routes.

There is no new GM or UB allocation. The public 33-tensor arena, 408-byte body descriptor, maximum resident UB of 116480 bytes, shared-expert branch, projections, rounding boundaries, active table, all five body joins and the final outer `EndPhase` retain the parent contract. The inherited system-workspace calls retain their installed CANN first-selection behavior. The independent source freeze preserves the parent and rejects profile or padded-GU builds.

At M12, the input split reads 73728 A8 bytes instead of 589824 and performs 36 conversion blocks instead of 288. It still writes 589824 packed bytes in 576 copies. There are 36 active AIV tasks with 24 CUBE groups; a 1536-column split would fill all 48 AIV workers but increase copies to 768. The selected 2048-column geometry isolates repeated conversion work without changing the transfer count. Metadata reconstruction and reduced worker occupancy can offset this saving. Shared GU runs concurrently with this phase, so an eightfold reduction of split arithmetic is not an eightfold latency claim.

Eight CPU contracts check 2176 valid ownership configurations with arbitrary within-expert permutation, all 65536 INT8 pairs, unchanged helper and synchronization statements, buffer reuse, independent include guards, frozen public validators and the actual 408-byte descriptor. Their numerical scope is exact integer splitting and address ownership. Device acceptance retains all 30 production boundaries plus the complete active table against both existing oracles, including changing routes and zero-input/probability fixtures. A performance decision requires the same-address complete FFN comparison against `8430`, both owner arenas, sixteen independent weight banks and at least 30 independent event samples per arm.

Build-v2 compiled with CANN 9.2 and passed all eight frozen CPU contracts on x86 and AArch64. Parent and candidate Torch 2.12 libraries loaded together with matching public schemas and NPU initialization false. The library is `ecbf7937796d407405dd920d6c48b7148da380b6e12e04717b049e19aed650a6`; its [handoff and source identities](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/a3-194/ffn-token-split-build-v2/handoff.json) record 88 source files and six compiled artifacts. Those hashes were verified after transfer to a3-194.
