# Token-owned input split with terminal completion

This independent candidate starts from token-split library `ecbf7937796d407405dd920d6c48b7148da380b6e12e04717b049e19aed650a6`. Its only device change replaces the final global kernel `EndPhase` with `PipeBarrier<PIPE_ALL>()` and `DataSyncBarrier<MemDsbT::DDR>()`. The namespace is `tilert_ffn_token_terminal`; the C entry is `ffn_token_terminal_launch`. The original source and library remain separate.

Token-owned split outputs are published by the unchanged phase-one mixed-core join, before GU reads them. The five body joins, all matrix and vector arithmetic, active-expert table, shared branch, route probabilities and every BF16 boundary remain unchanged. After `routed_body::Forward` returns, its matrix objects and local buffer handles have left scope. `TokenOutputs` has completed its local stores and publication fences; no in-kernel consumer, UB allocation, reset or system-workspace reuse follows. Each core drains its own pipelines and GM stores before returning, and same-stream consumers wait for completion of the global task. This argument applies only to the standalone global entry. The callable body retains its existing caller publication obligations.

The public ABI retains 33 scratch tensors, the 408-byte body descriptor, the 112-byte shared-input record and a maximum resident UB allocation of 116480 bytes. No extra GM or UB is allocated. System-workspace selection remains the parent's CANN 9.2 first-selection behavior. Profile builds are excluded because their final trace writer is outside the NoTrace contract.

The numerical harness retains both frozen reference chains and all original boundaries. Four additional outputs are consumed by immediate `copy_` operations inside the candidate graph: routed routes, routed output, scaled routed output and combined output. Both source outputs and consumer destinations are poisoned before each replay. This tests global-task publication in addition to the arithmetic comparison.
