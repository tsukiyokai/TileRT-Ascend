# One-launch local layer chain

This entry composes input AddRMSNorm and dynamic A8 quantization, indexed or shared-indexer attention, and the complete NZ FFN in one mixed AIC/AIV launch. Attention source is frozen from `8deff750`; FFN source is frozen from `381febf9`. The input requires a separate BF16 residual and M1–32 with 16 or 24 core groups.

Both TP reductions are identity cuts. The actual rank-local attention partial feeds the post-attention norm and FFN; no external post-AR1 value is substituted. Output owners are FFN `bridge[10]` and retained residual `bridge[1]`. This local dataflow is a composition test, not the TP16 decoder's mathematical result.

The [device comparison](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/vendor-hook-local-chain-wide-v1-a3-194/summary.json) passes M1/2/12/32 with 24 core groups and C8 index caches on one A3 die. Two consecutive layers use the original Decoder6/7 classes with synthetic parameters and official weight postprocessing. The reference runs the original input norm and A8 quantizer, accepted indexed/shared attention and complete FFN separately. All 3,488 raw-byte checks across 32 changing-input cases match, including retained arithmetic boundaries, complete caches, persistent top-k and immediate consumers. Layer7 reads layer6's output and residual directly through the same GPU owners. Each width has eight distinct input, live-length, slot and output witnesses.

The [official ACLGraphWrapper comparison](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/vendor-hook-local-graph-wide-v1-a3-194/summary.json) also passes all four widths: four captures, 32 explicit replays and 3,488 raw-byte checks. The captured work contains two local launches, the persistent top-k transfer and preallocated observation consumers. Python runs once per capture and never during replay. The actual capture stream differs from both the eager stream and the outer graph-capture stream. Both TP cuts remain identity; multi-rank reduction validation remains required.

With [N512 Down host preparation](../layer_down_n512/README.md), matched M12 graph timing saves 20.22 and 21.21 us per indexed/shared two-layer pair against three native norm/attention/FFN launches. All 60 alternating pairs favor the whole layer. Both arms use the same owners and Top-K copy, and the timed baseline has no norm-output copies. The measurement repeats two synthetic weight sets with identity TP reductions.

The [CANN 9.2 build](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/layer-local-chain-build-v4/summary.json) compiles both mixed entries and links with no undefined symbols. Library `609c973e` exports both entries, host-record preparation and current-stream submission. The ARM contract checks all eight M1/2/12/32 and 16/24-group configurations, rejects mismatched producer addresses and missing residuals, and records a 1,600-byte kernel argument record. Torch212 loads the library with no mapped die and no NPU initialization.

The caller owns validated ND activations, metadata and caches, original NZ expert weights, prepared tilings, all scratch tensors and the current submitted stream. Input norm outputs have separate storage; normalized BF16 feeds the indexer while its A8 codes/scales feed Prolog. The attention callable's final publication barrier precedes FFN reads. FFN retains its original global-task terminal completion. A consumer inside the same kernel would need a publication boundary before reusing its output or UB.

`host.py` retains every tensor and both opaque host records for the comparison harness. Parent operators must validate those tensors before preparation. The C++ shim sets the device and obtains `c10_npu::getCurrentNPUStream().stream()` before launching, which submits queued TorchNPU producers. Indexed and shared attention require their respective prepared tiling owners; the indexed front-tiling prefix is not a shared tail tiling.

`prepare.py ATTENTION_BUILD FFN_BUILD NEW_OUTPUT` verifies both libraries and every frozen source before copying them into an isolated tree. The generated source includes the attention MLA-tail definition before the FFN copy: their only difference is the standalone tail's combined-scale instantiation; the shared FFN explicitly requests the same combined-scale helper. Parent arithmetic, tilings and internal joins remain intact. Kernel compilation, original-chain numerical comparison, changing-input graph replay and matched timing are separate gates.
