# Down N512 tiling

This candidate starts from the validated `381febf94f918cc7393019b6f99ec8dc38e9a5cc9e63b2d49d5fe483158e3ff2` FFN. Only Down's host tiler adds `SetFixSplit(-1,512,-1)`. The returned ND and NZ tilings must both be M64/N512/K128, with the recorded loop depths, buffer counts and resource sizes; an unexpected tiling fails preparation. The device source, GU static configuration, original shared quantization, per-expert ownership, all five body joins and terminal publication remain unchanged apart from independent public symbols.

For every expert count `1 <= c <= 32`, `SetSingleShape(2*c,6144,128)` still has one M tile and one K tile. Twelve N512 tiles replace twenty-four N256 tiles. The result retains row stride 6144 and the same compact high/low row addresses. N512 spans eight complete INT4 NZ N64 blocks, so it needs no repacking or tensor view. Each K128 INT32 dot has magnitude at most `128*64=8192`; the FP16 MSD and later BF16 boundaries are unchanged.

The [installed CANN 9.2 host-tiling audit](../../../../docs/evidence/ascend-decode/megakernel-device-20261021/integration/ffn-down-geometry-source-audit/README.md) records L0A 8192 bytes, double-buffered L0B 65536 bytes, single-buffered L0C 131072 bytes and L1 397312 bytes. L0B and L0C exactly reach the A3 platform limits. Down has the AIC after its existing `pipe.Reset()`; the concurrent shared-store phase uses AIV UB. No other live AIC allocation shares these L0 buffers. The full B matrix already fits L1 in the parent, so this change does not imply lower HBM traffic.

The namespace is `tilert_ffn_down_n512`; the C ABI is `ffn_down_n512_launch`. The 33 scratch tensors, 408-byte descriptor, 112-byte shared-input structure and 116480-byte peak UB allocation retain the parent ABI. The original Decoder norm/MLP remains the numerical oracle. The inherited `parent-check.py` uses historical shared arithmetic and is not an acceptance test. First require raw-byte equality of GU/Down integer results and all production outputs across counts, layouts and changing graph replays; then compare full FFN event time with 381feb using both common-address arenas and at least 30 independent samples per arm.
