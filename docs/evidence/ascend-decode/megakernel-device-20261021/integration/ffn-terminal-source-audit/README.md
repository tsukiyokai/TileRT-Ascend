# Complete FFN terminal completion

The frozen `8430ef17d068ce5a1cdbe4915ba189ca38c666322d8726a42091f8acb3b36f84` entry has no device consumer after its final output writes. Replacing only its final global `EndPhase` with `PIPE_ALL` then `DDR` preserves the source completion obligations below. This audit changes no implementation and makes no performance claim. All 83 parent source hashes were checked; `audit.json` contains exact paths, hashes and numbered excerpts.

The parent prefix is `docs/evidence/ascend-decode/megakernel-device-20261021/integration/ffn-active-token-join-build-v1/build-v1/`.

- `source/kernel.cpp:21–39`: the global wrapper constructs one `TPipe`, invokes the bridge and body, then performs the final `EndPhase`. No subsequent reader or allocation follows it. The initial bridge system-workspace selection remains unchanged; the later `SetSysWorkspace` does not imply a workspace switch in CANN 9.2.
- `body/source/routed_int4/routed_body_native.h:739–790`: `shared.Store` and every down projection precede retained barrier4. `Project` calls `mm.End()` at 199, and the down matrix object leaves scope at 777. - `source/output_native.h:48–57`: task `t` owns token `t/4` and columns `1536*(t%4)..1536*(t%4+1)`, with tasks assigned by `t=worker+2*blocks*k`. Each final element has exactly one writer. - `body/source/routed_int4/routed_int4_front.h:99–130`: active-list scalar updates target UB. `S_MTE3` precedes the full 1056-byte DMA to GM; retained barrier0 follows `PIPE_ALL` and `DDR` at 177–180. The final region has no pending scalar GM table writes.

Installed CANN 9.2 `kernel_tpipe_impl.h:80–85` invokes `Destroy` in the ordinary destructor. `DestroyWithoutPipeAll` at 543–576 drains local queue events and AIC M_MTE1 events; `Destroy` at 579–588 adds local PIPE_ALL outside superkernel builds. `Reset` at 591–611 uses the same queue-drain loop and then resets local resource state. At this terminal return there is no later allocation requiring that reset. Body-local TBuf objects carry no remaining data movement after the explicit drains, and every matrix operation has ended before barrier4.

Installed `dav_c220/kernel_operator_sync_impl.h:363–403` adds mixed-core handshakes, not a DCache clean. Final outputs use DMA; the active table was also published by DMA earlier. The runtime programming-model source states that a later task on the same stream starts after completion of the preceding task. `PIPE_ALL` plus DDR establishes local completion; completion of the mixed kernel task establishes the dependency for a later same-stream consumer. It does not make one early AIC return equivalent to completion of the whole task.

A callable continuation is a concrete counterexample: an AIC may finish while an AIV still owns an unfinished 1536-column output tile. A following norm, TP transfer or scratch reuse within the same global kernel can then read stale values. That interface must retain a mixed join or another explicit producer/consumer protocol. Cross-stream consumers likewise require an event edge. The terminal change is confined to the standalone global entry, with all earlier barriers, ordinary destruction and local drains retained.

The decisive numerical gate queues consumers of combined, scaled-routed, routed and route outputs immediately after the kernel inside the same graph, poisons those destinations before replay, and checks raw bytes over changing inputs and all supported geometries. This tests the terminal dependency; it does not turn a callable return into a globally complete stage.
