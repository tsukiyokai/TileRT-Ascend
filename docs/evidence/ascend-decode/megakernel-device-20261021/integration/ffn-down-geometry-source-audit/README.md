# Down geometry on CANN 9.2

The host-only [probe](tiling_probe.cpp) calls the installed `MatmulApiTiling` with the parent's INT4 A/B, INT32 C and full Down shape `[64,128] × [128,6144]`. The [22 results](tilings.jsonl) cover ND and NZ independently. No Torch or device runtime is initialized. [Installed source identities](installed-identities.json) pin the A3 platform limits and SDK implementations.

The first candidate is N512 with unchanged M64/K128. `SetFixSplit(-1,512,-1)` returns baseM64/baseN512/baseK128, depthB1=stepN=12 and one M/K step in both layouts. The parent has N256 and 24 N steps. Double-buffered L0A uses 8192 bytes, double-buffered L0B 65536 bytes, single-buffered L0C 131072 bytes and L1 397312 bytes. L0B and L0C exactly meet the limits in `Ascend910_9392.ini:46–49`. The full 393216-byte B already fits L1; the tiling change alone establishes no HBM reduction.

The alternative M16/N1024 and M32/N1024 requests do not retain K128: the installed tiler selects K64 and two K steps. M64/N1024 fails. N1024 therefore gives six output copies but twelve MMAD updates per M block, while counts above eight or sixteen require extra M blocks. A dynamic row bucket can avoid some padding, but adds tiling selection and must preserve all counts through 32. It is a separate experiment, ranked after the pure N512 change.

Redistributing tiles across experts is a third mechanism. At 65 nonempty experts and 24 cores, whole-expert assignment gives at most three experts per core; distributing all 1560 N256 tiles evenly would give 65 tiles per core instead of 72 on the heaviest owner, a 9.7% equal-cost work imbalance. This is not a latency bound: counts, cache reuse, `Init/End` cost and unequal expert work remain. The earlier stripe experiments provide no general mixed-route win, so a new scheduling scheme needs its own measured source of imbalance before implementation.

The installed [N loop](installed/asc/impl/adv_api/detail/matmul/scheduler/iterator/n_loop/n_loop_norm_base.h) computes `ceil(singleShape/baseN)` at lines 140–149; the [M loop](installed/asc/impl/adv_api/detail/matmul/scheduler/iterator/m_loop/m_loop_norm_base.h) uses the same rule. Counts 1–32 retain one M64 tile and one K128 tile. [Fixpipe](installed/asc/impl/adv_api/detail/matmul/stage/copy_cube_out/copy_cube_out_fixpipe.h) keeps the original N stride at lines 451–492 and offsets the current N tile at lines 578–585. The compact high/low planes and row stride 6144 therefore remain unchanged. N512 is eight full INT4 NZ N64 blocks; no weight conversion is needed.

The [MMAD helper](installed/asc/impl/adv_api/detail/matmul/stage/compute/mmad_compute.h#L77) retains its small-M PIPE_M barrier when `(M/16)*(N/16)<10`. Counts below eight still satisfy that condition for both N256 and N512; fewer N tiles reduce the number of such iterations, not the condition itself. All INT4 K128 dot products fit INT32 exactly. The candidate preserves each FP16 MSD and BF16 output boundary, all original consumers and all phase joins. Numerical acceptance must inspect the valid integer products and final outputs before matched-address full-FFN timing decides whether twelve wider tiles are faster.
