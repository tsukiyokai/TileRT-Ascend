# Two-rank eager layer-chain harness

The frozen fixture compares two C2 layer launches, with two SHMEM reductions per layer, against the original input norm and accepted separate attention/FFN parents with actual two-rank HCCL SUM at both reduction sites. Layers6/7 retain full/shared-indexer selection, the persistent top-k copy, and separate retained residual ownership. Each case compares 113 raw tensor boundaries per rank. Additional gates require different rank-local attention/FFN partials and identical reduced tensors and retained residuals. This is an eager two-rank test with TP16-shaped controlled shards; it does not establish TP16 model correctness or graph replay.

The actual constructor and postprocessing remain visible in `source/constructor.patch`. The seven changed matrix names and all parameter geometries are checked against the accepted original layer record in `source/parameter_geometry.json`. Fourteen helper ranks participate only in Gloo constructor geometry and the ordered creation of groups as nonmembers; only ranks0/1 may initialize NPUs. Public CANN APIs check the requested physical mapping and peer access before model construction.

The actual Torch/TorchNPU2.12 CPU gate passed 20 contracts and five CLI controls, verified 825 overlay and 7,953 runtime files, co-loaded five libraries, and checked the C2 664/928/48-byte ABI. No NPU was mapped or initialized and no process group was created. The group-order test is a call-order model. CPU v1 stopped during the FLA import because a non-login shell selected the older system C++ runtime; v2 used the device launcher's existing login-shell environment, with frozen sources and libraries unchanged.

The manifest pins every original input; this archive includes the new source, full constructor transformation, runtime library identities and both CPU results. Device reports are archived separately by the runner. The window is allocated before execution on the declared stream, retained across widths and inputs without host epoch resets, and released only after synchronization and a two-rank rendezvous. No binary objects are stored here.
