# Two-rank native FP32 HCCL timing harness

Frozen staging v3 `5f187350…` passed the actual Torch 2.12 CPU gate: 21 inherited eager contracts, eight graph contracts and ten timing contracts; 868 staging and 7,953 runtime files; six native DSOs; no mapped NPU and no NPU initialization. The [CPU report](cpu-v2/report.json) includes the original three-process Gloo nonmember probe, whose three participants exited successfully. This archive contains source and CPU evidence. The subsequent [M12 device measurement](../vendor-hook-tp-timing-m12-v1-a3-194/summary.json) passes and saves 23.049/23.264 µs per two-layer pair across two compute arenas, with 60/60 paired wins.

The comparison keeps C2 `c2b72e46…`, indexed attention `8deff750…`, shared attention `64108f6f…`, FFN `381febf9…` and native norm `40a9e3c0…`. The primary control uses four retained FP32 buffers, BF16-to-FP32 conversion, real HCCL2 SUM and conversion into the same BF16 production owners. Literal project conversion and ordered rank sums remain event-external numerical checks. Launcher values `HCCL_OP_EXPANSION_MODE=AIV` and `HCCL_DETERMINISTIC=true` are checked before Torch import. Their source contract is recorded [separately](../layer-tp-timing-protocol-v1/README.md).

M12 uses two retained compute arenas, each with a repeated weight bank and the same production addresses for both arms. Both arms keep the layer6-to-layer7 top-k copy. Four official graphs per arena cover one or 16 two-layer pairs for control and candidate. Eight changing inputs check all 113 production boundaries per rank; repeated pairs and repeated replays test fixed-input idempotence without a host epoch reset. Reports derive expected epoch increments from submitted graph calls; they do not read the device counter.

Each graph size uses 30 alternating paired event samples with 30 replays per event. The pair statistic takes the larger rank interval for each arm before subtraction. CPU gathers, snapshots and observation copies are outside events. Each event has nine tail checks, followed by complete post-run checks. The result describes two controlled TP16-shaped shards and a combined fusion/collective comparison, not TP16 model correctness, isolated fusion benefit or TPOT.

[handoff.json](handoff.json) records the exact device command, library identities, source hashes and CPU evidence paths. The accepted earlier BF16 HCCL graph [wide gate](../vendor-hook-tp-graph-wide-v1-a3-194/summary.json) remains a distinct correctness result. It did not pin this AIV FP32 timing baseline.
