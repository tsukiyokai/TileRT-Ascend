# C2 consumption of N1024 Down tiling

The [source and build-command comparison](source-contract.json) supports passing the accepted N1024 host tiling to the unchanged C2 library. All 49 embedded FFN C++ files match the frozen `381febf9` parent. Against `bbd52e42`, 48 remain identical after namespace normalization; the sole changed embedded file is the host tiler. Both actual kernel commands use `dav-2201`, `-O2`, `-ffp-contract=off` and the same five defines: `ROUTED_ROW_BALANCED`, `ROUTED_SHARED_PIPELINE`, `ROUTED_INPUT_FRONT`, `SHARED_W8_DYNAMIC_PERFORMANCE_QUANT`, `ROUTED_ACTIVE_LIST`. No profile, Fixpipe-half or GU-MDL define is present. C2 additionally includes its attention/SHMEM source; this comparison does not assert identical generated machine code.

In frozen `routed_body_native.h:65–76`, Down uses the dynamic `Projection` template; only GU uses `kGateTiling`. Lines 166–174 load every `TCubeTiling` word, and lines 711–737 read `body.scratch[kDownTiling]`, initialize Down, and execute `SetSingleShape(2*count,6144,128)`. Its destination remains the complete INT32 product with stride 6144. N1024's recorded 200-byte descriptor is `c207230a…`, with base M/N/K=32/1024/64. The full 200 bytes, not just those three dimensions, define the accepted tiling. Counts 17–32 require two M tiles. The existing original-FFN and local-chain hot-row gates cover that case; they do not execute this descriptor inside C2's two-rank chain.

Three concrete rejection conditions remain essential. Loading `bbd52e42` while retaining the old preparation can silently leave N256 in `body[7]`. Replacing a TensorImpl/storage after capture can invalidate the owning host validator or leave a stale pointer in the captured C ABI record. Testing only the three base dimensions can accept a different depth, double-buffer or workspace configuration. The minimal host change must use `bbd52e42.prepare/forward_out` together, retain its original owners, check the complete `c207230a…` bytes before capture and after each arm, and build C2's local record from those exact addresses. No device-source or C2 rebuild is required by this route.

The original 16 MiB matmul system workspace, dynamic expert rows, five body joins and final C2 `EndPhase` before AR2 remain unchanged. FP32 HCCL control, literal conversions, rank-distinct real shard weights, all 113 boundaries, active-table poison, persistent top-k copy, actual capture-stream ownership and the window without host epoch reset must remain in any later comparison. Changing the preparation must not switch the control back to BF16 HCCL.

The [same609 N512/N1024 measurement](../layer-down-n1024-timing-v1-a3-194/summary.json) saves only 1.435/2.487 µs per two-layer pair, with 51/60 wins. It does not establish a C2 gain. The retained evidence supports a small host-only integration if needed for deployment consistency; it does not justify prioritizing another broad device experiment over the unresolved TP16 reduction-order contract. No new fixture, compilation or device run was performed for this review.
